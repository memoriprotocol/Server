ПРОПУСКА — ИСПРАВЛЕНЫ КОНКРЕТНЫЕ ПРИЧИНЫ НЕРАБОТАЮЩЕГО ОКНА
1.Убран цикл passInfo -> passInfoResetPush -> новый passInfo. Родной клиент
  всегда перезапрашивает данные по reset; раньше сервер отправлял его и на ответ.
  Теперь чтение не сбрасывает окно и не пересинхронизирует весь аватар.
2.Недельные повторяемые задания автоматически дают XP при выполнении. В родном
  TaskItemView нет кнопки получения; сезонные задания/еженедельная отметка
  остаются ручными. Автовыдача — реконструкция по UI, не код retail-сервера.
3.taskExp содержит только недельный опыт с лимитом из PassScheme(30000).
  Сезонные награды, отметка, покупка уровней и подарочный XP не засоряют этот счётчик.
  В понедельник недельный счётчик/задания сбрасываются, сезонный XP сохраняется.
  Текущий период:понедельник00:00 UTC, вход — сутки UTC. Retail-часовой пояс
  не восстановлен; native getWeekIndex проверен только с UTC-календарём клиента.
4.Прогресс/XP/монеты пропуска приходят родными push без закрытия окна.
  Ошибка отправки повторяется с абсолютными значениями, без новой выдачи XP.
5.Старый накопительный progress мигрирует в totalProgress; клиент видит остаток
  текущего повторения. Полученные награды не повторяются. Старые незабранные
  недельные выполнения могут начислиться один раз в пределах недельного лимита.

НАГРАДЫ / СОХРАНЕНИЯ
Награда пропуска/SevenDay и отметка получения сохраняются одной записью players.json.
Ошибка записи откатывает только план игрока, не заменяет объекты всех онлайн-игроков.
Ошибка уведомления после записи не превращает сохранённую награду в неуспешную.
Повторная синхронизация не начисляет её второй раз. Очередь уведомлений в памяти;
после перезапуска сохранённая награда/прогресс восстанавливаются обычным входом.
Проверены все120 уровней обоих пропусков,15 строк магазина и7 наград SevenDay.
Нужно свободное место по прежним правилам: при полной оружейной сумке выдача оружия
отклоняется без потери отметки получения. Отдельного переполнения в почту не добавлено.
SevenDay учитывает новый день при нахождении онлайн, не требует перезахода.

РАСХОДЫ ЗОЛОТА
Подключено задание CostGold к имеющимся покупкам магазина/торговца, маунта/подарка,
лотерее оружия, смене героя у мастера, сбросу талантов и повышению уровня пета.
Расход и прогресс в одной записи; алмазы не считаются золотом. Гача учитывалась ранее.
Само поведение/цены этих систем остаются ранее восстановленной реализацией.
При смене аккаунта очищаются прежние очереди событий/платёжных уведомлений.
