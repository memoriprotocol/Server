STAGE48 — ПОРТАЛЫ СЕЙФ-ЗОН И ПЕРЕХОДЫ
Клиент 3.12.7. Сервер 0.26.0-stage48-safezone-portals.
Промежуточная сборка. Полное восстановление всех механик 1:1 НЕ завершено.

УСТАНОВКА И ЗАПУСК
1. Остановить сервер и сохранить резервную копию своих баз.
2. Server_Full из архива скопировать поверх установленного Server_Full.
   Сохранить свои Server/data, .env и приватные настройки. Баз игроков
   и приватных настроек в архиве нет.
3. Запустить START_SERVER.bat (либо node server.js из Server_Full).
   Полностью перезайти в клиент. /status покажет версию Stage48.
4. Если Stage47 уже установлен, сайт и клиент повторно копировать не нужно:
   в Stage48 они не менялись. Для установки поверх более раннего этапа
   приложены накопленные Website_Full (только исправленные файлы сайта)
   и Client_Payment_Addon. Их установка и настройки описаны в README_STAGE47_RU.txt.
   Electron Index и игровой Cocos Index не меняются.

ПОРТАЛЫ MAP2
По последнему указанию пользователя: ровно один портал в центре каждой
сейф-зоны. Пять зон из неизменённой конфигурации Stage44 дают пять точек:
  1. center: x=40.83250, y=-363.63175
  2. center-001: x=6.61500, y=20212.30655
  3. center-002: x=113.63200, y=-16567.82570
  4. center-003: x=-15827.16100, y=-125.53440
  5. center-004: x=16627.92500, y=-125.53440
Порталы есть в основном мире и мире новичков, в отдельных комнатах.
Это назначенная пользователем расстановка, не заявление о найденных
исторических серверных координатах. Границы зон, городские стены,
их модели/позиции/мосты/коллизии сохранены из Stage44.
Используются родной EntityType.portal2=1028, prefab portal/portal,
battle.iob.sendPortal2sInfo, CommandTransport(from,to), transportEnd и
createPortal2 для миникарты. Выбор в родной панели переносит героя:
сервер меняет координаты/движение, клиент получает перенос камеры и
lastOut-анимацию портала назначения. HP, боевой уровень и оружие сохраняются.
Подменённые индексы, удалённый вход и повтор в пределах секунды отклоняются.
Модель родного near-trigger имеет радиус240. Серверный допуск390 и
антиспам1000мс — локальные настройки, не восстановленные retail-константы.
Перенос сейчас немедленный, без восстановленной задержки/эффекта входного
канала. Визуальное отображение и доступность кнопки в Windows ещё не проверены.

ПЕРЕХОДЫ И ЛОГОВО MAP5 — ЧАСТИЧНАЯ РЕАЛИЗАЦИЯ
Родной NPC408 The Carrier открывает панель подземелий. Для Map5 подключены:
— создание и выход из комнаты подбора, вход по roomId, 1–4 игрока;
— передача лидера, исключение участника, локальное объединение комнат
  по кнопке автоматического подбора;
— проверки основного мира, живого героя, уровня80, лидера и CD;
— реальный отдельный экземпляр Map5/mode6, родной fubenRoomEnterOkPush,
  battle.iob.enter и обратный onPlayerLeave с загрузкой IOGame;
— перенос без повторного login/detach, поэтому уровень, XP, HP, экипировка
  и статистика текущей жизни сохраняются. Отключение/перезаход в игру,
  как и прежде, завершает боевую жизнь и сбрасывает боевой уровень;
— свои пять боссов1309/1316/1317/1318/1319 с родными типами и prefab,
  размещённые внутри извлечённых областей arena/maps/map_5;
— уровни115 из PVEScheme для режима6. В общей MapProduction у1317 стоит120,
  но для PVE выбран явный уровень115 из PVEScheme. Это зафиксированное
  разрешение расхождения таблиц, а не доказанная логика исходного сервера;
— обычные Personal/Team награды DropDeath Map5, XP группы экземпляра,
  настоящий сундук10029 после босса и его собственная таблица дропа;
  это больше не вызывает UNSUPPORTED_SPECIAL_DEATH_REWARD;
— происхождение редкого лута из сундука сохраняет ID исходного босса
  для уже существующей общей серверной рассылки;
— босс и его сундук не респаунятся в завершённом экземпляре;
— таймер3600с с первого loadingFinished, возврат после убийства пяти боссов
  через15с, выход через отдельного NPC419, освобождение экземпляра;
— CD300с и сброс за10 алмазов из PVEScheme, сохранение одним коммитом;
— ошибка записи награды оставляет босса живым, без частичного XP/сундука;
— ошибка доставки перехода оставляет выбранную комнату для повтора;
— AI/движение/эффекты используют ID своей карты, а не стены и воду Map2.

ВАЖНО О БОЕВОМ СОСТОЯНИИ MAP5
Урон и специальные эффекты ВСЕХ 17 умений этих пяти боссов пока НЕ реализованы.
Сервер посылает нативные события начала/каста и ведёт базовый AI, но полного
боевого поведения логова ещё нет. Сводка каждого навыка находится в
retail/audits/STAGE48_MAP5_SKILL_COVERAGE.json. Не выдаём подключение карты,
комнаты и наград за завершённое восстановление данжа.
Не реализованы в этом этапе: целевые бонусы TargetArgs, особый дроп варианта
1317/120, другие данжи13–16, Undead6, платное PVE-воскрешение, приглашения
через inviteReq и все варианты особых порталов. Неподдержанные операции
возвращают ошибку, остальные карты не подменяются Map5.
Позиция выходного NPC419 (Born+450 поX), допуск650 и подбор конкретной точки
внутри родной области являются локальной серверной политикой. Геометрия
полигонов родная; алгоритм случайного выбора исходного сервера неизвестен.

ПРОВЕРКИ
455/455 серверных тестов, включая28 новых проверок Stage48.
Оригинальные функции BSNetworkController.onPlayerLeave и
IslandController.matchSuccEnterScene выполнены в VM с реальными серверными
protobuf-пакетами: выбрана новая комната, освобождается старая сцена,
вызывается IOGame. Это контрактная проверка, НЕ запуск Windows/Cocos.
Проверены центры всех пяти порталов, запрет удалённых команд, состояние
движения/HP/XP, лидерство/лимит группы, отдельные экземпляры, дроп сундука,
откат ошибки записи, таймер, выход/отключение, повтор доставки и смерть
при возврате по таймауту. Клиентский визуал и полный бой требуют проверки.
Диагностика: /diagnostics/navigation. Тесты: npm test из Server_Full.
