УСТАНОВКА
1. Остановить сервер, сайт и клиент. Сделать резервную копию баз игроков
   и двух изменяемых файлов клиентского адаптера.
2. Server_Full скопировать поверх установленной Server_Full. Сохранить
   свои Server/data, .env и приватные настройки. В архиве баз игроков нет.
3. Website_Full — накопленные исправленные файлы сайта, а НЕ весь сайт
   с ресурсами. Скопировать поверх существующего Website_Full; сохранить
   его local.config.json, .env, data и остальные файлы. В этом этапе новый
   server.js сайта добавляет доставку оплаченной покупки и правильный USD.
4. Для платёжного оверлея два файла из Client_Payment_Addon/resources/app
   скопировать в resources/app установленного клиента по тем же путям:
   local-steam-adapter.js и cocosExport/web-desktop/local-bootstrap.js.
   Требуется уже установленный локальный клиент, который загружает эти
   адаптеры. Оригинальные Electron Index и Cocos Index НЕ меняются.
5. Запустить START_SERVER.bat (или node server.js из Server_Full), затем
   сайт его обычным способом. Полностью перезапустить клиент/лаунчер.
   /status должен показывать 0.25.0-stage47-saved-changes.

ПЛАТЕЖИ И ОВЕРЛЕЙ
Игра создаёт заказ по шести родным StoreScheme, с серверной ценой и
валютой USD. Награда фиксируется при создании как ItemNum + Extra;
это явно выбранная трактовка полей базовой награды и бонуса клиента,
без подтверждения формулы исходного коммерческого сервера.
Оверлей открывает существующую /pay/<orderId>?token=... страницу сайта.
Реальная проверка провайдера остаётся на сайте (Stripe webhook). После
подтверждения сайт вызывает /auth/internal/payment-confirm; игровой
сервер сверяет заказ, пользователя, товар, сумму и валюту и сохраняет
валюту вместе с квитанцией одной транзакцией. Повторы не начисляют снова.
Клиентский authorizationMall не может выдать валюту. Подтверждённая
покупка обновляет баланс и передаёт родной txnAuthorization в UI клиента.
Закрытие оверлея снимает блокировку UI, но не подтверждает оплату.
Если сервер был недоступен, провайдер повторяет webhook, а открытая
страница повторяет проверку статуса. Оплата офлайн сохраняется в аккаунт.

Настройки должны совпадать с существующим сайтом:
— sharedSecret/HEROS_WEB_SHARED_SECRET — связь сайта с игровым сервером;
— paymentSecret/LOCAL_WEB_PAYMENT_SECRET — подпись платёжных ссылок;
— publicBaseURL/LOCAL_WEB_PUBLIC_BASE_URL (или HEROS_PAYMENT_SITE_URL
  для сервера) — адрес вашего сайта, по умолчанию http://127.0.0.1:3000.
Сервер читает local.config.json соседней Website_Full; собственные настройки
из архива не подставляются. Заглушка CHANGE_ME_LOCAL_SHARED_SECRET для
создания заказа не принимается. Настройки Stripe и режима тестовой оплаты
сохраняются из вашего сайта; реальных операций этой сборкой не выполнялось.
Для удалённого сайта используется HTTPS; callback игрового сервера в этом
варианте доступен только локальному сайту через loopback и общий секрет.
Схема с сайтом на отдельной машине требует отдельного сетевого адаптера.
Не считаем проверенным в Windows: отрисовку iframe, ввод карты/3DS и полный
боевой клиентский UI. Проведены серверные и модельные проверки адаптера.
